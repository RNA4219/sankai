# 理解

取り出した指示が何を達成・維持し、どの範囲で使えるかをつかむ。Yomiyasuの「意味を保つ原則 → 文脈の把握 → 文章化 → 前後の照合」という構成を参考にする。整理用のメモと、利用者に渡す説明は分ける。

## 1. 基本原則

次の4点を、読むときと説明した後で照合する。

- **主張**：誰が何について述べ、条件・理由・例外がどこに掛かるか。
- **比重**：主な論点、補足、例示、比較対象を入れ替えていないか。
- **強さ**：義務・禁止・推奨・許可・可能性・保証を区別したか。
- **文の働き**：事実、評価、依頼・決まり、仮定、引用等を保ったか。予定を実績、例を規則に変えていないか。

作者の理由や意図を一般論で補わない。役立つ推論は、根拠と仮説を分けて示す。原文を正しく説明できることと、原文の技術的・業務的主張が正しいことは別である。

## 2. 実行手順

### 1. 文脈と文の関係を押さえる

対象・版、利用者の問い、読み手、用途、長さの指定を確認する。分解で得た原文位置と関係を使い、必要な節と前後だけを読む。段落の話題、主体と対象、理由・例示・但し書き・並列・順序を区別する。単なる参照を必須の依存や実行順に変えない。

判断が難しい箇所だけ、次を短い内部メモにする。文ごとの網羅表や専用のスキーマを作る必要はない。

| メモ | 残す内容 |
|---|---|
| 根拠と主張 | 原文位置、主体・対象、何を述べる文か |
| 条件と関係 | 適用範囲、否定、例外、前提、ほかの記述との関係 |
| 強さと比重 | 義務等の強さ、主な論点か補足・例か |
| 理由と不明点 | 明示された理由、仮説、分からないことと影響する判断 |

### 2. 意味と不明点を確かめる

何を達成し、何を守り、省くと何が満たせなくなるかを、メモと根拠から説明する。同じ対象・環境・条件で比較し、対象が違う規則を衝突と呼ばない。優先順位が不明なら勝手に決めない。

取り出した単位ごとに、他の部分がなくても意味が通るか、共通条件や参照先と組で使う必要があるかを確かめる。境界の妥当性は仕事と条件の関係から説明し、別ファイルだから独立、同じファイルだから不可分とは判断しない。分けると条件が失われるなら、分解へ戻って境界か依存の示し方を直す。

| 状態 | 扱い |
|---|---|
| 明示／推論 | 原文の記述と解釈を分け、解釈を仕様や許可にしない |
| 未取得 | 読んでいない参照先と、影響する範囲を示す |
| 欠落 | 判断に必要な記載がない。適用先の未提示情報とは分ける |
| 曖昧／衝突 | 読み方の分岐、または同一条件で両立しない記述と根拠を示す |
| 許された選択の未選択 | 選べる条件が明示されていれば、欠落や承認待ちにしない |

不明点ごとに、それが分からないと決められない判断を特定する。関係が示せない変更まで確認待ちにしない。未定義の情報を、既に存在する必須条件として扱わない。必要な判断ができるなら、関係のない不足は残したまま説明を進める。

### 3. 説明を書く

利用者の問いへの答えを先に書き、理由と必要な不明点を添える。分解に記した条件一覧を理解で再掲せず、条件が働く理由や関係を説明する。溶解へ渡す条件も原文位置で結び、同じ一覧を増やさない。内部メモはそのまま出力しない。

指定された文字数を、分解・理解・溶解を合わせた出力全体で守る。重複や不要な再掲から削り、条件・例外・根拠・重要な不明点を削って帳尻を合わせない。短くした結果、主語や条件の掛かり先が分からなくなったら書き直す。

### 4. 原文と照合する

基本原則の4点について、説明で足したこと・落としたこと・掛かり先が変わったことを点検する。原文にない理由、因果、優先順位、変更許可、事前確認を足していないか確かめる。原文から説明、説明から原文の両方をたどり、欠落と増補を直す。引用の一致や文字数内に収まったことだけで成功としない。

## 3. 返すもの

取り出した指示本文に、原文位置を伴う「この単位で取り出せる理由・指示の意味・利用条件」を短く添える。不明点は、それが影響する利用や変更の判断とともに示す。指示本文を説明で置き換えず、全項目に同じ欄や見出しを作らない。

外部確認が必要な箇所には指定された検索・原典追跡の手段を使い、既存の根拠で足りる調査は繰り返さない。委任が許可されていれば問いと対象を限定し、統合時に根拠と条件を確認する。委任だけでトークン削減を主張しない。

Yomiyasuによる推敲も依頼された場合は、説明後に同スキルを読み、原文・対象資料を渡して所定の検査まで行う。構成を参考にしただけで「Yomiyasu適用済み」と報告しない。意味の修正と文章の推敲は記録で区別する。

人に渡すときは、溶解まで含めて照合した結果を[HTMLで説明する](html-explanation.md)。説明・引用・原文を読み分けられる形にし、理解の内部メモをそのままページ化しない。
